## Architecture: four layers, one placement rule

```
 INSTITUTION   people + amicode governance: authority, promotion, merge windows,
               the agenda, the autonomy ladder            (who may act)
 SYSTEM TWO    LLM casts: director, implementer, experimenter, critics, architect
               (generates, critiques, plans)              (what to try)
 SYSTEM ONE    TypeSafe Jev: choose/score among declared options, calibrated,
               pinned, fail-open, zero free text in       (what first)
 MECHANICAL    verifiers, tests, gates, CI, Telaio's corrector, deploy gate
               (ground truth; the only label source)      (what is true)
```

**Placement rule.** Every decision point is one row in a registry naming its
layer. A decision may *consult* a lower layer. It may never be *decided* by a
layer above its row. System One never generates and never shrinks a mechanical
floor. System Two never labels. The Institution's acts are attributable to a human
principal (A15).

**amicode's role.** amicode is the Institution layer and the System Two
orchestrator. Telaio is the Mechanical + System One host for Julia campaigns: it
adjudicates verification and owns its warrants. amicode calls Telaio (#119 is the
seam) and does not copy it.

## Decisions

- **A0: The spec executes itself.**
  - (a) **`amico spec slices <spec>`**, a third subcommand beside `review` and
    `validate` (`spec_verb.ts`).
    - It parses this spec's Plan table (columns `# | tier | step | repo |
      task_type | after`) into `plan_compile`'s step shape (`CompiledStep.needs`),
      so there is no second plan format.
    - It files one issue per row in the row's repo (cross-repo sub-issues of the
      PRD; all repos are in `harmoniqs`) and sets GitHub blocked-by edges from
      `after`.
    - It is idempotent (a second run files nothing). Each issue carries a
      provenance line naming the verb and the spec's design hash.
    - CLI-only in v2.1 (not exposed as an MCP tool).
    - v2's remaining work is filed once as a tracking issue (row 37). v2's table
      has no `after` column and overlaps these rows, so it is not re-parsed.
  - (b) **census-lite**: one script, GitHub-derived (authoritative).
    - It reports open framework slices with age, loops since the last framework
      commit, merges with and without bypass, override deploys, open-PR depth,
      and overlay file count (read from `manifest.json` `counts`).
    - It renders daily into the morning brief with a render timestamp and
      coverage; a missing source is a named gap, never a zero.
    - **Stall tripwire:** a framework tier that has not moved in 72h becomes the
      brief's top line.
  - (c) **`amico reserve take|waive`**. "take" is used because `amico claims`
    already names another concept.
    - The ledger-init verb (v2 D5c) requires a reservation (taken slice or
      waiver) to create a campaign ledger. Census-lite lists campaigns without
      one. That is the enforcement point; card prose is not.
    - A taken slice expires after 5 days without a commit or PR on it.
    - A waiver is a human-principal event (A15) with a TTL.
    - A **hotfix class** bypasses the reservation for fleet incidents, capped at
      2 per week and counted in census-lite, so urgent fixes are never blocked.
    - One owner: Notturno #510's "reservation leases" consume `amico reserve`
      rather than define a second mechanism.
  - (d) **Tier 1 is done when it is merged and deployed**, not when it is written.
    Aaron's steps are named rows: the App setup (row 3), the protection change
    (row 20), and the merge and deploy of each Tier-1 row.
- **A1: Glossary split.**
  - *Jev* means TypeSafe System One only.
  - *Critic pass* means a fresh-context LLM judgment dispatch: one lens,
    code-enforced verdict vocabulary, receipted.
  - v2 D16, Notturno v1 D3, and amicissimo CONTEXT.md's "Jev pass" read as
    critic pass. This is recorded as an amendment note beside the Notturno spec,
    not an edit to it, and it lands before #509 builds the gate.
  - **Lens routing:** the critic lens set has a **mechanical floor** derived from
    the diff's paths and classes (the same shape as Notturno's blast-radius
    ceiling). Jev may add lenses above the floor or reorder them, never remove
    one. Its consult state is bank questions over path-derived features, with
    zero free text.
- **A2: The decision registry.**
  - `config/decisions/registry.toml` (amicode), mirrored by id in Telaio and
    arJev.
  - One row per decision point: id, layer, owner repo, consumer, fallback.
  - A test enumerates call sites of each Jev client, including wrappers and
    re-exports, and fails on an unregistered one. A planted wrapper is the
    positive control.
- **A3: One Jev contract, four thin clients**, shared as data and fixtures, not
  a library.
  - (a) **Versioned models only.** Every client refuses any non-versioned model
    id, including env overrides, and discards a response whose concrete version
    differs from the pin.
  - (b) **One qualification store on the hub** in Telaio's record shape (battery
    id, model version, bank digest, Brier/reliability, TTL). It keeps Telaio's
    write allowlist and load filter, so research records stay inert. There is one
    readiness verb. A seam without a valid record runs its deterministic path.
  - (c) **Version dead-man.** A receipt whose version differs from the seam's
    qualified version demotes the seam to deterministic and files one agenda item
    per (seam, version), deduped. A seam re-promotes only by re-qualification.
  - (d) **Memoization** keyed by (state digest × pinned version × bank digest),
    checked against record validity before every cache read. An unchanged subject
    is not re-asked; a changed subject is.
  - (e) **One receipt schema**: seam id, primitive, state digest, version, bank
    digest, verdict, confidence, latency, usage, fail code. The local placement
    allocator stamps `provider:"local"`.
  - (f) **Advisory spend**: each seam names a budget object (the A12 Authority
    shape). The cap is 10% of it. No budget means no calls. An over-estimate is a
    breach that closes spend until a human renews it.
  - (g) **Wire conformance**: arJev's captured fixtures are the contract every
    client's tests replay.
- **A4: The verdict bus (the label economy).** One append-only hub ledger of
  typed label events: `{source, subject_ref, verdict, evidence_ref, principal,
  ts}`.
  - **Admission rules:**
    - CI conclusions only from base-branch workflows the PR cannot edit,
      excluding reruns and quarantined/flaky tests.
    - Dispositions (finding accepted or overridden; un-archive) only when
      `principal` is a human.
    - Events authored under an agent identity, or derived from any model's
      judgment, are rejected.
  - **Wave-1 sources:** PR CI conclusions, deploy-gate outcomes, human
    dispositions of reviewer findings, human un-archives, experiment
    VERIFIED/REFUTED. Admitted corrections join with row 13.
  - **Consumers:** Jev batteries, arJev `calibrate`, Telaio corpus schema 2
    (#153), the census. amicode becomes the label factory the Jev stack lacks.
  - Critic calibration on dispositions is **advisory only**. Acceptance rate is
    not defect rate.
- **A5: Corrections are the eval set.**
  - Land #1678 (rebase) and one of amicissimo #492/#493 (close the duplicate).
  - Each admitted correction becomes a **replay fixture**: the preceding context,
    the correction, and a **mechanical** check.
  - Corrections with no mechanical check stay findings, not fixtures.
  - Fixtures pass the secret scan (A6) and are redacted before creation. They are
    stored privately (amicissimo or the personal vault, never the public amicode
    repo).
  - They run in the hub-side gate (the deploy gate / Notturno), not public CI.
  - A fixture must fail on the pre-fix commit (positive control).
  - A PR touching a mode card, skill, or the director protocol runs every fixture
    whose cluster touches the changed surface, plus a held-out set it cannot
    choose.
  - The census tracks **recurrence per human-admitted cluster**.
  - Behavior-gap findings route to the reservation queue as protocol slices.
- **A6: One night pass over the chat DB.**
  - Curation, shard watch, open-thread scoring, the flywheel distill, and
    corrections share one watermark and one per-session feature digest under
    Notturno. `skill-freshness-night` and `role-parity` stay separate units by
    name.
  - **Shadow first:** the unified pass runs beside the live timers for 7 nights
    with output diffs. The old units stay installed but disabled as the rollback,

  - Shard watch reports `unreachable` as a named outcome.
  - **The secret scan runs first**, before any projection feeds a vendor or LLM.
    Rotation findings carry only session/part id, credential type, and a
    fingerprint.
- **A7: Liveness registry.**
  - It generalizes the existing `notturno-morning-deadman` to every periodic job
    (Notturno passes, arJev daily, the night pass, census-lite, the deadman
    itself).
  - Liveness means *a successful artifact within its completion window*, not a
    start time.
  - Every unit gains `OnFailure=`.
  - Misses bundle into one brief line, and alert after 2 consecutive misses.
  - The registry is diffed against the hosts' actual timers, cron, and launchd
    entries, so an unregistered job is itself a finding.
- **A8: arJev becomes the research system's eyes.**
  - (a) **Vault digest**: `--post vault` writes a dated digest note per weekday,

  - (b) **Paper → campaign routing**: one Jev choice per finalist over the active

  - (c) **Insights root**: `insights/` and open hypotheses become a second fold

  - (d) The *jev-hot, lexical-buried* divergence tail feeds the lit pass as

  - (e) **Citation labels**: a paper cited as a prior by a hypothesis round that

- **A10: Critic passes and real protection on main** (amends D13, D16).
  - The D13 reviewer, the D14 architect, and spec-review tier-2 critics are

  - The reviewer verdict is posted as the **`reviewer-pass` check-run by a

  - Branch protection on `main` becomes:
    - required checks = the existing CI jobs + `reviewer-pass`;
    - **one required code-owner approval**, with `CODEOWNERS` naming humans only

    - **`enforce_admins: true`**.
  - Today one human cannot approve his own PRs, so the review requirement forces

    - `known-flaky`: may pass or fail, with a TTL.

    CI fails on any failure outside both lists and on a `known-fail` test that

  - (d) **Skills lint**: it already runs green against `lint-skills-known.txt`.

  - (e) **Named-outcome gate for UI actions**: every user-action handler resolves

  - (f) **Overlay budget**: overlay count goes in census-lite. New engine/UI
