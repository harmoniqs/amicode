# Autonomous R&D system v2 — one source of truth, protected self-improvement, verified compaction

## Context

The v1 framework (spec-20260907-011500, spec-20261008-054129) built the three-posture
director, the session ledger, the gate packs, and the deliberate/spec machinery. Six
load-bearing failures are now evidenced by the rd-framework campaign's own record
(session-20261008-rd-framework-live-skills) and the live state as of 2026-10-21:

1. **The dev gate dissolved behind a shadow lane.** Fleet fixes rode
   `live-test/*` branches deployed by ops while their PRs sat unmerged; the live plane
   became canonical over version control ("the live frontdoor carries UNCOMMITTED
   drift — live copy is canonical", ledger 2026-10-10). Live state: 55 open PRs; the
   campaign's own core (#1734 spec, #1735 skill merge, #1736 todo discipline) still
   open drafts; `#1555` needed a 567-commit rebase. The `#1784` fleet fix merged fine —
   urgent work moves, framework work stalls.
2. **Self-improvement always loses the scheduling contest.** The queued framework
   workstreams are all still open: #1740 (live skills / boot-frozen cache; sequenced
   behind #1716 by prose, not by GitHub blocked-by metadata), #1741 (manifest staging),
   #1742 (error-correction gates). Skills remain boot-frozen — a merged SKILL.md edit
   needs a hub restart — so the system cannot deliver its own improvements mid-flight,
   and no lane protects framework capacity.
3. **Protocol is prose where it should be code** (the substrate law says verbs own
   enforcement): ledger-at-kickoff failed in this very campaign (created two days
   late); the todo derived-view rule is asserted by nothing at runtime; the deploy
   provenance ritual was bypassed twice (`475302c9`, the 2026-10-12 swap) and the
   deploy gate stamped GATE-APPROVED on a failed smoke until caught.
4. **The anti-gaming clause has an observability blind spot**: client telemetry was
   dead ~4 weeks before detection; the s2/s3 wedge streamed silence a full day+.
   Absence of signal was read as absence of failure. The dead-man doctrine (client
   #1752, upstream #1758, engine #1759) fixes the three known surfaces reactively.
5. **One human is every queue**: decider, sole reviewer, deployer, provenance
   checker. The review queue was recorded thirteen-deep in October; it is 55 now.
   Nothing batches, prioritizes, or expires the human decision surface.
6. **The system has no self-metrics**: no aggregation of loop counts, EXHAUSTED
   rate, advisory latency, queue age, or rebase debt. Improvement without
   measurement is vibes.

**Compaction (grounded 2026-10-21).** The engine fork carries two parallel compaction
systems — V2 (`packages/core/src/session/compaction.ts`, pre-turn
`compactIfNeeded` + overflow retry) and V1 legacy (the path dispatched subagents
actually run, `packages/opencode/src/session/compaction.ts` + `prompt.ts`) — both
single-shot model summaries with fixed templates, unverified output, static chars/4
token estimates, no phase awareness. A hallucinated summary is injected unvalidated.
A subagent's working context dies at its step limit; only final text crosses back —
the eaten-return pattern that cost the campaign repeated rediscovery. Telaio.jl
already has the good design in production (`src/Context.jl`, `src/Digest.jl`): a
five-stage mechanical ladder before any model call, `verify_summary` anti-fabrication
gate (mechanical claim-matching against the dropped span), EWMA-calibrated token
estimator seeded from provider usage, digest re-grounding from the event spine.

**Fork position (measured 2026-10-21).** `harmoniqs/opencode` is a PUBLIC fork of
`sst/opencode`; its local `dev` is a pure upstream pointer, 0 proprietary commits,
**5936 commits behind** upstream dev (last visible sync attempts late August:
`notturno/merge-upstream-2026-08-24`; upstream is itself reworking compaction —
`cleanup/effectify-remaining-compaction-tests`). All Harmoniqs engine work lives on
topic branches and the committed overlay in `harmoniqs/amicode` (PUBLIC:
`packages/app-bundle/overlay/packages/{core,opencode,...}`, manifest-recorded).
Telaio.jl and amicissimo are PRIVATE. Plugin hooks exist on the V1 compaction path
(`experimental.session.compacting`, `experimental.compaction.autocontinue`);
V2 hook coverage is an open slice-scoped question — **a V2 seam slice is scheduled
(S6) so the decision cannot silently protect only V1**.

**The report lane (designed, stalled).** #1700/#1701 (1–2 page LaTeX loop report,
provenance-stamped numbers, mechanical page-cap/slot/provenance gate,
receipts-not-gates failure semantics), #1712 (research-loop cadence amendment),
#1719 (v2: embedded evidence figures) — all open, merge-ordered
`#1701 → #1711 (formulation.toml emission) → #1719`. Its **needs-you slot** is
already half of the human-throughput answer.

**Role-card gaps (grounded 2026-10-21, user-directed).** The hypothesizer card
briefs on the findings ledger and prior notes only — **no lit pass**: no vault
papers grep, no arXiv API round, no arJev digest priors, despite sota-review
already defining the discipline (vault-first, arXiv over HTTPS, SIDECAR
stage-then-count). The insight circulation loop is unwired end-to-end: analyzer
insight proposals stage but promotion at close is suggestion-not-step; arJev
digests land in the vault but no brief carries them as priors; nothing feeds the
vault's insight corpus back into paper-ingestion ranking or the research agenda.
The experimenter card carries no API discipline — no layer-skill-first rule, no
API-friction issue filing, no codebase-development debrief — so API pain
surfaces as workarounds, not as issues and improvements. On the develop side,
the declared-but-never-executed error-correction gates (spec-20261008 D5 →
#1742: reviewer subagent, layer-skill loading, architecture critique) are
still open, and **no role owns cross-repo propagation** — canonical-repo
decisions (Piccolo, Telaio, the engine) do not systematically reach their
dependents (Legato, Legatissimo, Intonato, the apps), and package/skill
crosslinking rides on the nightly dream-connect instead of campaign boundaries.

## Decisions

- **D1 — The live-test lane becomes the release train.** One serving train branch
  per repo at any time (`live-test/*` naming retained — renaming costs churn, the
  rule does the work). Ops deploys only from the train head; the provenance record
  names it at every deploy, and the train's head history is retained so any prior
  head can be restored. **Branch expiry: any branch serving the live plane must
  land in an open consolidation PR within 14 days of first deploy, and that PR must
  be green and mergeable; the exemption caps at 28 days total** — past it, the
  branch rolls back off the plane or reconciles. The landing target is the repo's
  record branch: `main` for `harmoniqs/amicode`; for the opencode fork (whose `dev`
  is an upstream pointer) the train consolidation PR is the record. **The
  house-approved hotfix valve stays**: an override deploy (`AMICODE_DEPLOY_OVERRIDE`
  with recorded reason) must commit-forward onto the train head within 72h or
  surfaces as a train violation; the watchdog recognizes override-tagged records.
  **Rollback rule: restoring a prior recorded head is always sanctioned** — it
  names the restored head in the provenance record and files a root-cause issue;
  a proven-bad head is never reconciled into the record (the 2026-10-12 lesson),
  and its 14-day clock is suspended while flagged bad. Consolidation PRs open at
  each merge window, run the full-suite gate, and merge human-only (unchanged).
  Multiple concurrent serving lanes are dissolved by this rule — one plane, one
  train.
- **D2 — Reconciliation drains forward, never rewrites.** First slices of the v2
  campaign: (a) commit the live frontdoor's uncommitted drift (the live copy is
  canonical — the recorded rule from 2026-10-10) as a branch feeding the train;
  (b) land the report lane in its merge order (`#1701 → #1711 → #1719 → #1712`);
  (c) land the stalled framework core #1734/#1735/#1736 — the skill merge is
  already live-staged, so the PR catches the record up to the plane **as a one-time
  catch-up; live-staging ahead of a merged PR remains a violation of the
  skills-integrity path**; (d) the remainder drains per D3's agenda. Historical
  records untouched.
- **D3 — The review agenda + merge windows.** The report machinery's fill contract
  (#1700) becomes posture-agnostic and carries a **decision agenda** at every
  campaign boundary: open PRs grouped by lane with gate evidence, recommended
  action, and age; framework debt with age + impact; expiring train branches;
  pending deploy windows. **Every recommendation carries its verbatim command
  evidence inline** (suite output lines, PR links, provenance rows) — the agenda
  curates, the human decides; post-hoc audit is possible because merges are
  recorded against the recommendations that proposed them. **Merge windows open
  only on the human's live idle signal** (the 2026-10-16 pattern) — the agenda
  defines a window's contents, never its timing, so batched merges never
  concentrate deploy bounces onto live fleet sessions. Stale PRs (> 21 days)
  carry expiry recommendations (merge-queue-first / close-with-crosspointer /
  needs-discussion); closes are visible against lands in the census
  (`landed_pr_ratio`), so closing-to-improve-metrics cannot masquerade as
  draining.
- **D4 — Protected self-improvement: per-campaign reservation.** director-core
  amendment + both packs carry the rule: **every autonomous campaign's first AFK
  loop works the next open unblocked framework slice by the standing priority
  order** — A1 #1740 first (it unblocks all mid-flight delivery), then E1/E2
  #1742 (the critique gates, per Aaron's 2026-10-21 emphasis), then A2 #1741,
  then the tooling fixes; within a tier, oldest first — from the framework
  backlog. #1716 is unblocked ahead of A1, and the informal
  "#1740 behind #1716" sequencing becomes GitHub blocked-by metadata
  when this lands). A blocked reserved slice skips to the next unblocked one —
  the reservation never stalls a campaign's close. **Runtime enforcement is the
  report gate, not agent prose**: every campaign-boundary report carries a
  reservation row (slice worked, or waiver), and the fill-contract gate fails a
  report that lacks it. **The waiver is human-recorded at the campaign's close
  merge window** (it rides the close receipt the human signs), never an
  agent-authored ledger line.
- **D5 — Prose-to-code: mechanize the disciplines** (the substrate law — anything
  checkable lives in a verb):
  - (a) **deploy gate stamp bug**: GATE-APPROVED stamps only on green smoke — a
    regression test pins it, against the deployed gate script itself;
  - (b) **deploy provenance as a script + a deploy dead-man**: the three-way
    agreement (source == train head, binary sha-verified, record updated same-op)
    runs mechanically; a watchdog cross-check (records/disk sha disagreement)
    alerts — the same doctrine as the stream dead-men, applied to deploys. The
    expiry clock reads two clocks: the provenance record AND the server's own
    handshake log timestamps (`server.log` binaryHash lines — agent-unwritable),
    surfaced together in the agenda so a maintained record cannot quietly reset
    the clock;
  - (c) **ledger-init probe at kickoff**: a Step-0 bare-verb check (the ledger
    exists and parses before the first dispatch); the deliberate skill's own
    Step-0 probe is fixed — it tests `--help`, which the CLI rejects, yielding a
    false `manual` (this exact bug cost the 2026-10-08 spec its tool review);
  - (d) **dead-man doctrine in director-core**: "every long-lived stream carries a
    dead-man; every diagnostic surface a heartbeat" — one line in the core, and
    the two known-uncovered surfaces (`/global/event` route, dev SSE) are filed;
  - (e) **todo derived-view becomes a named pack-gate procedure** in both packs:
    at every loop boundary the director verifies the session todo list mirrors
    ledger §3/§5 — named so it is greppable and auditable, still director-run.
- **D6 — Compaction: private plugin, minimal-first, upstream-cheap.**
  - (a) **Location**: the ladder/verify/calibrate/re-ground implementation lives
    in a PRIVATE repo (amicissimo or a new private package) shipped as an engine
    plugin riding the existing compaction hooks; public repos carry at most
    hook-seam additions, never the implementation. **A V2 hook-seam slice is part
    of S6** — if V2 lacks the hooks, the seam lands publicly (minimal) and the
    implementation stays private; verify_summary's acceptance names BOTH paths so
    green on V1 alone cannot pass. Nothing compaction-shaped publishes until an
    explicit human flip (later, its own deliberate decision).
  - (b) **Landing order** (each its own slice): 1. `verify_summary` — the
    mechanical anti-fabrication gate (claim-matching against the dropped span;
    Telaio's ≥3-claims/≥0.75-score constants as the starting point), on V1 AND
    V2; 2. EWMA-calibrated token estimation (seeded chars/4, corrected by
    recorded provider usage, with a test that recomputes the correction from a
    recorded completion's real usage); 3. **structured EXHAUSTED receipt** — the
    cast cards' return contract gains files-touched / next-intended-step /
    blockers, so a step-limited cast hands back a context digest, not just final
    text, and a consumer parses it (the parent's resume path or a Telaio
    verification expression — the receipt is exercised end-to-end, not just
    authored); 4. the staged mechanical ladder; 5. digest re-grounding.
  - (c) **Upstream posture**: no deep-internal compaction patches in the fork —
    the plugin shape keeps the ~6k-commit upstream merge cheap while upstream
    itself reworks compaction; upstreaming any of this is a later human-only
    decision.
- **D7 — The report lane is the boundary record for both postures.** #1712 binds
  research; a develop-mode binding follows: the develop loop's boundary report
  renders the review agenda (D3) + a verdict-table digest through the same fill
  contract. Read-only projection, visibly stale when stale, receipts-not-gates.
  The reservation row (D4) and the census line (D8) ride every boundary report.
- **D8 — The census (system self-metrics).** A small script aggregates campaign
  ledgers + the GitHub queue: loops/week, EXHAUSTED rate, advisory closure
  latency, review-queue depth + age, rebase debt (commits-behind per open PR),
  deploy rollback count, landed-vs-closed ratio. **Ledger-derived metrics render
  under a SELF-REPORTED label; GitHub-derived metrics are authoritative.** The
  census declares its ledger-shape contract (the two known shapes from #1700); a
  parse failure is a receipt line naming the ledger — never a silent undercount —
  and the census artifact carries its own render timestamp + coverage count
  (the heartbeat rule applied to the census itself).   **The census measures,
  never gates, in v2** — gating is a later decision made on real data.
  Spec-acceptance checks read the underlying records directly, never the
  census; the two census-rendering criteria (`census_ledger_shape_parse_receipts`,
  `crosslink_density_in_census`) are meta-criteria about the census artifact
  itself, not criteria checked through it — the same carve-out both.
- **D9 — Sequencing.** S1 train formalization + drift reconciliation (D1, D2a) →
  S2 report lane lands + develop binding (D2b/c, D7) → S3 agenda live + merge
  windows drain the queue (D3) → S4 first reservation: #1716 then A1 #1740 (D4) →
  S5 research-side role-card amendments (D10–D12) → S6 dev-side critics: E1/E2 +
  the architect + crosslink pass (D13–D15) → S7 mechanization slices (D5) →
  S8 compaction plugin slices 1–3 + the V2 seam (D6b, D6a) → S9 census (D8) →
  S10 compaction slices 4–5.
- **D10 — The hypothesizer's literature pass.** Every hypothesis round opens
  with a lit pass **run by the director (the parent), not the hypothesizer** —
  the hypothesizer card stays `bash: deny` and permission-isolated; the cast
  pattern holds: **vault grep first** (papers, reading cards, package docs — a
  hit is faster and better than the network), then the **arXiv API via the
  sota queue** (`amico sota papers`), with matches staged per sota-review's
  SIDECAR discipline — they stage beside the session ledger, count only after
  the PI stamp, and the staged lines join the hypothesizer's brief as priors.
  A queue-timeout or fetch failure is a **named outcome cross-referenced to a
  queue artifact** (the lock log or cache-miss record), never bare loop-log
  prose, and never blocks the loop. The brief also carries the **arJev digest
  notes as standing priors** (the daily digest already ranks against the vault;
  its accepted notes join prior experiment notes as hypothesis inputs).
  Hypothesis cards cite their lit provenance like every other number.
- **D11 — The insight circulation loop (vault ↔ arJev ↔ agenda).** Wire the
  existing pieces end-to-end, one loop with four edges: (a) **insights in** —
  the analyzer's insight proposals stage to `ledger/environment-proposals/`
  (already in the research skill) and **promotion at campaign close becomes a
  step, not a suggestion**: the boundary report carries the promotion row and
  the human promote path (`amico env promote` / dream-promote) is the only
  door into the vault's insight corpus (the circulation-stages-before-it-counts
  invariant); (b) **papers in** — arJev digests land in the vault and join the
  hypothesizer's brief as priors (D10), and the vault's insight corpus is the
  ranking substrate arJev already ranks against, so promoted insights improve
  ingestion by construction; (c) **agenda out** — amico-strategy reads the
  vault: the insight corpus informs the research agenda, and the boundary
  report's census line includes the insight-flow counts (proposals staged,
  promoted, digests consumed as priors);   (d) **the full circle is measured**: a promoted insight is cited as a prior
  by a hypothesis round **outside the campaign that produced it** — the
  circulation receipt; the producing campaign's agent-controllable obligation
  is staging + surfacing the promotion row only. This is
  wiring, not new machinery — every piece exists; the spec closes the loop.
- **D12 — Experimenter API discipline.** The experimenter card gains three
  duties: (a) **layer-skill first** — load the target package's `*-dev` skill
  before authoring (the proper API, not archaeology); (b) **API friction
  becomes issues, not workarounds** — friction encountered mid-experiment is
  filed on the package repo while the evidence is fresh (the experimenter has
  the tools), with issue refs recorded in its note's structured `api_friction`
  field; the director surfaces them in the boundary report; (c) the note
  carries a **`codebase_development` section** — upstream improvements
  observed while working in the package (API design, ergonomics, performance
  traps), which the analyzer folds into insight proposals and issue seeds to
  the develop posture via the existing handoff. An honest
  none-encountered receipt is falsifiable: **the analyzer's existing
  skill-friction scan cross-checks it** — analyzer-found friction against a
  reported-none is a mismatch the boundary report surfaces. Improving the APIs
  the experiments depend on is part of the experiment's record.
- **D13 — Julia critique agents land (E1/E2, #1742, promoted in the
  reservation).** The develop integrate phase gains the **mechanical reviewer
  pass**: the director dispatches the code-review subagent (Julia/quantum
  criteria — idioms, allocations, test meaningfulness, architecture) over each
  green slice before it merges into the integration branch; the reviewer cast
  is never the implementer cast (enforced by dispatch, not promise). Layer-skill
  loading lands for the implementer (E2: the implementer reads the target
  package's `*-dev` skill first). Reviewer findings are advisory to the
  director — but a **load-bearing advisory** (one that names a concrete failure
  mode: the criterion it breaks, quoted) blocks the DIRECTOR's merge of the
  slice branch into the integration branch, never the human's PR merge; a
  human override at the window is recorded in the boundary report. The
  reviewer's dispatch is receipted, so veto-delay and rubber-stamping are
  both visible in the record.
- **D14 — The architect role (canonical-repo propagation).** A new architect
  subagent card, briefed on the Harmoniqs conventions corpus — the layer-dev
  skills, the packages' AGENTS.md files, the ADRs and doctrine notes, the
  design system — with two duties: (a) **architecture-critique pass** during
  the campaign's integrate phase (at least once per campaign, cadence the
  director's call — advisory findings; the old framework's declared E3, now
  owned by a named role); (b) **the propagation pass** at campaign close:
  decisions made in canonical repos (Piccolo, Telaio, the engine) that apply
  to their dependents (Legato, Legatissimo, Intonato, Strumento, the apps,
  the skills) land as **crosslink findings + issue seeds** — canonical-repo
  performance and architecture decisions propagate to siblings as
  first-class artifacts, not folklore. Findings carry provenance stamps
  (source decision → target repo/skill, canonical artifact path) and the
  receipt is the **follow-up artifact** (a filed issue, an added crosslink, an
  accepted seed) — the finding alone does not pass. The architect proposes;
  the promote-path invariant holds (findings stage, humans merge the PRs
  they generate). Self-improvement and integration become a role, not an
  aspiration.
- **D15 — Crosslinking as a standing artifact.** Packages and skills
  crosslinked and building on each other: (a) the architect's close pass
  proposes missing cross-references across the campaign's touched packages
  and skills — proposals STAGE (the circulation invariant); applying them
  runs under dream-connect's own contract on the personal vault, and
  crosslinks into promoted vaults ride the promote path (dream-connect's
  densification moved from nightly-only to campaign boundaries for the
  active surface); (b) every layer-dev skill references its siblings where
  a real dependency exists — auditable by the skills-integrity lint; (c) the
  census renders **crosslink density** (per touched package/skill: distinct-
  note connection count, self-links excluded, campaign-over-campaign delta)
  —   measured, never gated, labeled vault-derived (self-reported), and
  quality-denominated so self-link spam cannot inflate a future gating
  baseline.
- **D16 — Jev passes become the CLI's judgment substrate.** `amico spec
  review`'s tier-2 critics and `amico plan compile`'s critic dependency ride
  fresh **Jev passes** from the hub's routed pool (glossary: a fresh-context
  judgment dispatch, one lens each, code-enforced verdict vocabulary,
  receipted) instead of an external critic binary — this box's permanent
  `approved-mechanical` condition ends, tool-run `approved` verdicts return,
  and plan compilation comes back. The deliberate skill's Step-0 probe fix
  (D5c) lands with it: the probe uses a bare verb, and its result names the
  critic substrate truthfully (pool critics vs mechanical-only). The
  substrate is the same one the notturno merge gate (spec-20261021-071109
  D3) and the D13 reviewer gate ride — one judgment mechanism, three
  consumers.

## Measurement Protocol

**System-tagged criteria** (marked `system` below) depend on human merge
throughput. The agent's controllable obligation for them is rendering the agenda
and keeping consolidation PRs green and mergeable; if the human queue stalls,
these fail honestly and feed the census — failure is signal, not something to
manufacture a green against.

- `train_serving_branches_per_repo <= 1` — the provenance record of each deploy
  names exactly one train head per repo; the deploy watchdog (D5b) alerts on any
  deploy whose recorded source branch differs (override-tagged records excepted,
  per D1's 72h valve).
- `live_plane_unmerged_serving_days <= 28` (system) — for every branch recorded
  as serving the live plane: `days(now - first_deploy) <= 14`, or an open
  consolidation PR containing it that is green and mergeable, hard-capped at 28
  days total; `first_deploy` cross-read from the provenance record AND the
  server's handshake log timestamps.
- `landed_pr_ratio >= 0.75` (system) — of PRs resolved during the campaign, at
  least 75% merged rather than crosspointer-closed; closes are legitimate but
  visible.
- `skill_edit_reaches_running_session >= 1` — A1's epoch-reconcile integration test
  (a SKILL.md edit invalidates the per-Location parse cache and reaches the next
  turn) + one live hub probe receipt.
- `reservation_row_in_boundary_report == 1` — a campaign-boundary report without
  the reservation row (slice worked or human waiver) fails the fill-contract gate
  (test + one real render).
- `report_develop_mode_binding >= 1` — the develop skill/pack references the
  report fill contract (grep).
- `deploy_stamp_on_failed_smoke == 0` — the regression test runs against the
  deployed gate script: a failed smoke leaves no GATE-APPROVED stamp.
- `deploy_watchdog_disagreement_alerts >= 1` — a test injecting a records/disk sha
  mismatch produces an alert line.
- `verify_summary_rejects_fabrication_v1 == 1` and
  `verify_summary_rejects_fabrication_v2 == 1` — a synthetic fabricated summary
  (claims absent from the dropped span) is rejected on BOTH the V1 (subagent)
  path and the V2 (pre-turn) path of the deployed engine (separate test receipts;
  neither passes alone).
- `token_estimator_calibration_crosschecked == 1` — the EWMA row's correction,
  recomputed from a recorded completion's real usage, matches the row (test).
