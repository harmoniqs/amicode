# H0c seam spike — how the amicode-host obtains the opencode v2 server

- Issue: harmoniqs/amicode#2048 (part of #2043; spec §H0c/§H1; ADR 0039 D1–D3)
- Date: 2026-11-01

## Question

The published `@opencode/sdk` returns a *client*, not the server's request handler. The handler exists inside the unexported `internal/host.ts`. The host's route-fronting design (own deny-by-default auth, own `/amicode/*` routes, SSE pass-through with abort) depends on how the handler can be obtained. Which route should H1 build on?

## Candidates (as understood from reading code, before running anything)

Reading the code is **not** evidence for the comparison; it only fixes what to test. Each claim is tested by running code (criteria below).

1. **Deep import of `EmbeddedHost`** — `import { EmbeddedHost } from "@opencode/sdk/internal/host"` (not in the package `exports`, so a deep import would need a path trick or an upstream export PR). `EmbeddedHost.create(opts)` returns `{runtime, fetch, plugins, sessions, workspace, close}`. Serve `host.fetch` with `Bun.serve` behind OUR deny-by-default wrapper; add one custom route ahead of it. Embedded routes are built by `createEmbeddedRoutes`, which sets no password.
2. **`@opencode/server` route builder** (`exports: {"./*": "./src/*.ts"}`, so every file is importable). Three sub-shapes get exercised, because the package offers three entry points:
   - **2a** `createRoutes(options)` (honours `options.password`) as a Layer; add a custom `HttpRouter` route in-router; serve the router ourselves.
   - **2b** `ServerFetch.make(options, boot)` (`src/fetch.ts`): returns a web `fetch` handler, password enforced; we front it.
   - **2c** `ServerProcess.start(options, lifecycle?, transform?)` (`src/process.ts`): the stock Node server loop with a top-level `dispatch` auth gate, optional lifecycle (service registration is a lifecycle callback supplied by the CLI, not by this module) and a `transform` hook to wrap the app.
3. **Proxy to a stock `opencode serve --port N`** (no `--service`), temp XDG, host proxies and adds its own routes/auth.

## Procedure

1. Safety envelope for EVERY process: `env -u BUN_INSPECT -u AMICODE_ENGINE_INSPECT`; `XDG_STATE_HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` under `/tmp/opencode/h0c/xdg/<candidate>/`; `OPENCODE_DB` (and `database.path` in code) a fresh file in that dir; listen on 127.0.0.1 only, ports 51000–51999 that are free at the moment of binding (`ss` check first; 51223 is already held by something else); never `serve --service`, never `opencode service`; no credentials, no model calls; password is a throwaway literal.
2. Baseline hash of the hub's unit files / scripts / listening ports before; same after. The hub DB is written continuously by the live hub itself, so it is checked by (a) never being opened by any spike process (`/proc/<pid>/fd` scan) and (b) unit files byte-identical; its own mtime/size are recorded but cannot be required static.
3. For each candidate, a small script in `/tmp/opencode/h0c/` starts the server, runs C1–C9, prints PASS/FAIL lines; raw output saved under `docs/spikes/h0c-prototype/raw/` (copied from `/tmp/opencode/h0c/raw/`).
4. Server-side observation of abort (C6): count active `/api/event` subscribers on the server side (a wrapper counter around the stream body's `cancel`, plus if available the Bus subscriber count / open TCP connections via `ss -tn` on the port) before, during, and after abort.
5. Build the smallest prototype for the leading candidate in `docs/spikes/h0c-prototype/` (NOT a pnpm workspace member) with a check script and README. Then write Results + Decision.

## Decision rule (fixed now)

Prefer the candidate that passes C1–C9 with the **smallest upstream delta and fewest private imports**. A candidate that fails C3 or C6 cannot be chosen without a stated wrapper that fixes it. Ties go to the candidate that keeps plugin registration (C7) and workspace providers (C8) available in-process.

## Deviations from the pre-registration (disclosed)

1. **C5b added after the first run.** The first run showed the heartbeat stream emits its first `: heartbeat` at ~0–5 ms (the tick is immediate), so the pre-registered C5 ("≥ 1 heartbeat") passes trivially. C5b is the honest version: a *second* heartbeat arrives ≥ 10 s after the first (observed gap 15.0 s), i.e. the idle stream survives the 15 s cadence. C5 is still reported as registered.
2. **C3 is stricter than "standard routes"**: it probes five paths without credentials *including* an unknown path (`/nope`) and the custom path, as registered. Several seams fail it in their **bare** form; that is a result, not a test error.
3. **Each candidate is run twice**: `bare` (the seam served as-is) and `fronted` (behind our deny-by-default front). The registered pass rule is evaluated on `fronted`, because the host will always have a front; `bare` is reported because it shows what each seam gives for free.
4. **Two negative controls** were added so the harness can fail: Bun's default `idleTimeout` (10 s) and a proxy that ignores client cancel (both below). Without them a green C5/C6 would prove little.
5. **Server-side observation of C6 needed an instrumentation patch** in the *scratch* clone (`raw/instrumentation-event-feed.diff`, 3 log lines in `EventFeed`): the per-client subscriber map is private, and the client-side view (socket closed) cannot tell "connection closed" from "upstream subscription released". The patch only appends `subscribe`/`release subscribers=N` lines to a file; behaviour is unchanged.
6. **Route 2 split into three entry points** (2a `createRoutes`, 2b `ServerFetch.make`, 2c `ServerProcess.start`) because the published `@opencode/server` package offers all three and they behave differently. The brief's "route 2" is 2a; 2b/2c are reported because one of them (2c) is the only seam that is deny-by-default natively.

# Decision

**Chosen route: 1 — obtain the handler from `EmbeddedHost.create` and serve it behind the host's own deny-by-default front — enabled by one small upstream change.** Fallback if that change is not available when H1 starts: route 2a (works today, same criteria, more glue and more churn exposure).

Reasoning against the pre-registered rule (smallest upstream delta, fewest private imports, ties to in-process plugins and workspace providers):

- Routes 2b, 2c and 3 **fail C7 and/or C8** (no in-process plugin registration, no drivable workspace provider). If the host needs either in-process, they are out.
- Routes 1 and 2a both pass every criterion when fronted. Route 2a needs no upstream change but reaches into seven modules of the highest-churn package in the repo and re-implements the SDK host's glue; route 1 needs one export but then rides a 73-line module the SDK itself tests. Tie-break: route 1 (fewer private imports, thinner glue); route 2a remains a working escape hatch, proven here.
- Every route needs our front. None except 2c is deny-by-default on unknown paths, and 2c cannot register plugins. So the front is not an optional hardening; it is the auth boundary (route 1 has **no** auth of its own).

## The upstream change to propose (exact)

Title: `feat(sdk): export the embedded host (fetch handler, plugins, workspace) as @opencode/sdk/host`

> `@opencode/sdk` builds a complete in-process v2 server (`EmbeddedHost.create`) but only returns a client over it; the web-standard `fetch` handler, the plugin registry and the workspace service live in an unexported `internal/` module. Embedders that need to *front* the server (their own listener, authentication, extra routes next to the standard ones) currently have to reach into `internal/` by file path. This adds a `./host` subpath export that re-exports `EmbeddedHost` (`create`, `Interface`, `CreateOptions`, `EmbedOptions`) from `src/host.ts`, documents that `fetch` is a **trusted-caller handler with no authentication** (embedders must front it), and adds a test that (a) the handler serves `/api/info` and (b) aborting an `/api/event` request releases the server-side subscription. No behaviour change to `PromiseSdk.create` / `OpenCode.create`.

Concretely: `packages/sdk/package.json` gets `"./host": "./src/host.ts"`; new `packages/sdk/src/host.ts` is `export { EmbeddedHost } from "./internal/host"`; one test in `packages/sdk/test`. Optional second change, **not exercised by this spike** (**code-read**, `host.ts`): a `resume?: boolean` option on `CreateOptions` (default `true`) to skip the unconditional `SessionRestart.resumeSuspendedSessions` fork, so a host pointed at a persistent database controls when suspended turns replay. Land it in the harmoniqs fork first (the engine is already vendored from a committed overlay), upstream second.

## Risks

1. **No auth inside the seam.** Any path that reaches `host.fetch` without passing the front is an open v2 server. Mitigation: the front owns the only listener on `127.0.0.1`; C3 (five paths including unknown and custom) is an H1 CI check, not a one-off.
2. **Bun `idleTimeout` default (10 s) kills SSE** before the 15 s heartbeat (negative control above). The listener must set `idleTimeout: 0`.
3. **Abort depends on not touching the response body.** Passing `Response` through preserves cancel; buffering or pumping it leaks the upstream subscription (negative control). H1 needs a regression test of exactly this.
4. **Process coupling.** Engine and host share a process (crash, memory, event loop) unlike route 3. The hub is a long-lived multi-session process, so a host crash takes live sessions down with it.
5. **Unexported-module dependency** until the export lands; pin the upstream SHA and keep `run-all.sh`-style contract checks to catch signature drift (`host.ts`: 8 commits in ~2 months).
6. **One `effect` instance.** Context tags break with two copies; the host bundle must resolve `@opencode/*` and `effect` from a single workspace/install (the prototype symlinks a single `node_modules` for this).
7. **Defaults that bite**: `database.path` defaults to `:memory:` (sessions vanish — set a file path); `resumeSuspendedSessions` runs unconditionally on create **(code-read; not exercised)**.
8. **Observability**: the per-client subscription count is private; this spike needed a patched scratch clone to see server-side release. H1 should ask for an official counter (see exit criteria).
9. **Stock-client interference**: not a risk for route 1 — registration lives only in the CLI, confirmed by C9c and grep. It would become one if H1 ever called the CLI's `server-process`.

## H1 exit criteria this implies

1. `@opencode/sdk/host` (or the fork equivalent) exists and the host imports it by package name; no file-path imports into `internal/`.
2. The host binds exactly one listener, `127.0.0.1`, owned by the front; `host.fetch` is never reachable otherwise (test).
3. Deny-by-default test over ≥ 5 paths (standard, custom, unknown, `/api/event`, wrong password) returns 401 — C3 as an automated test, run in CI.
4. SSE: `server.connected`, a second heartbeat after ≥ 10 s, and abort ⇒ server-side release, checked against an **official** subscriber counter (not the spike's patch); includes the pump negative control as a failing-by-design test.
5. `idleTimeout: 0` (or an equivalent proven setting) asserted in a test that holds an idle stream > 15 s.
6. A persistent `database.path` is mandatory (startup fails on `:memory:`); behaviour of suspended-session resume on start is decided and tested (opt-out flag or documented replay).
7. Plugin registration and `workspaceProviders` reachable from the host's public code (C7, C8 re-run in H1's own tests).
8. Isolation check (C9) in H1's test harness: no `service*.json`, no 49374/49375, no hub DB open.
9. Pinned upstream SHA with a contract test of the seam's shape (`create` options, returned keys), so drift is a CI failure.

## Hub non-interference (acceptance criterion 4)

- **Units, scripts, unit states, listening ports: identical before and after** (`diff` of `raw/hub-unchanged.md` vs `raw/hub-unchanged.md` differs only in the hub database's own size/mtime lines).
- **The hub database cannot be byte-for-byte static**: it is live, written continuously by the running hub — including this very session, which runs on it (the file grew by ~24 MB and its WAL was rewritten during the window). What can be shown: (a) every spike process ran with `OPENCODE_DB` and all XDG dirs in `/tmp/opencode/h0c/xdg/<name>/`; (b) an fd scan of every spike process tree at the end of each run found **zero** descriptors under `~/.local/share/opencode` or `~/.amico/server` and the fresh DB open (C9a, all candidates); (c) no `service*.json` registration was written anywhere in the sandbox (C9c); (d) only ports in 51000–51999 were listened on (C9b); 49374/49375/4094–4296/9230 were never used. The fd scan is a point-in-time check at the end of each run, not a continuous trace: it is evidence, not proof, that the hub DB was never touched.
- Nothing was started, stopped, or restarted in systemd; no process outside this spike was signalled.

## Surprising

1. `ServerFetch.make` (public, 8 commits) already is "the v2 handler with a password" — the issue's premise that the handler only exists inside an unexported module is true for the *embedded* host but not for the published server package.
2. Of the five seams, only `ServerProcess.start` is deny-by-default natively; `createRoutes` and `ServerFetch` 404 unknown paths without credentials, and stock `serve` serves its UI shell before auth.
3. Bun's default `idleTimeout` silently defeats the 15 s heartbeat.
4. The first heartbeat is immediate, so a single-heartbeat check passes vacuously.
