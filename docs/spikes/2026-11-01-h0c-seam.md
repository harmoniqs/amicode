# H0c seam spike — how the amicode-host obtains the opencode v2 server

- Issue: harmoniqs/amicode#2048 (part of #2043; spec §H0c/§H1; ADR 0039 D1–D3)
- Date: 2026-11-01
- Upstream under test: `sst/opencode` `dev` @ `12f7e1b59a` (packages at version 2.2.5), checked out read-only-derived in `/tmp/opencode/h0c/upstream`
- Status: **PRE-REGISTRATION COMMIT** — everything below this line up to "Results" was written and committed before any candidate was run. Results/Decision are appended in later commits.

## Question

The published `@opencode/sdk` returns a *client*, not the server's request handler. The handler exists inside the unexported `internal/host.ts`. The host's route-fronting design (own deny-by-default auth, own `/amicode/*` routes, SSE pass-through with abort) depends on how the handler can be obtained. Which route should H1 build on?

## Candidates (as understood from reading code, before running anything)

Reading the code is **not** evidence for the comparison; it only fixes what to test. Each claim is tested by running code (criteria below).

1. **Deep import of `EmbeddedHost`** — `import { EmbeddedHost } from "@opencode/sdk/internal/host"` (not in the package `exports`, so a deep import would need a path trick or an upstream export PR). `EmbeddedHost.create(opts)` returns `{runtime, fetch, plugins, sessions, workspace, close}`. Serve `host.fetch` with `Bun.serve` behind OUR deny-by-default wrapper; add one custom route ahead of it. Embedded routes are built by `createEmbeddedRoutes`, which sets no password.
2. **`@opencode/server` route builder** (`exports: {"./*": "./src/*.ts"}`, so every file is importable). Three sub-shapes get exercised, because the package offers three entry points:
   - **2a** `createRoutes(options)` (honours `options.password`) as a Layer; add a custom `HttpRouter` route in-router; serve the router ourselves.
   - **2b** `ServerFetch.make(options, boot)` (`src/fetch.ts`): returns a web `fetch` handler, password enforced; we front it.
   - **2c** `ServerProcess.start(options, lifecycle?, transform?)` (`src/process.ts`): the stock Node server loop with a top-level `dispatch` auth gate, optional lifecycle (service registration is a lifecycle callback supplied by the CLI, not by this module) and a `transform` hook to wrap the app.
3. **Proxy to a stock `opencode serve --port N`** (no `--service`), temp XDG, host proxies and adds its own routes/auth.

## Criteria (fixed now; each is PASS/FAIL per candidate, with raw evidence from running code)

| ID | Criterion | PASS means |
|----|-----------|------------|
| C1 | Standard routes end to end | an info/health route answers, a session can be created and then appears in the session list (no model call) |
| C2 | Custom route | `GET /amicode/ping` with credentials returns our JSON |
| C3 | Deny-by-default | a request with NO credentials to (a) a standard path, (b) the custom path, (c) an unknown path (`/nope`), (d) `/api/event` all return 401 |
| C4 | SSE pass-through | `GET /api/event` with credentials yields a `server.connected` frame |
| C5 | Heartbeat | at least one heartbeat frame observed on that stream (expected ~15 s cadence; observe up to 40 s) |
| C6 | Abort forwarding | after the client aborts the SSE request, the server-side subscription is observed closing (a server-side counter / log / socket close that I can read, not inferred from the client side) |
| C7 | In-process plugin | a plugin registered in-process shows up (its tool/hook/RPC visible through the running server). For candidate 3: state it cannot, with evidence |
| C8 | Workspace providers | a trivial `workspaceProviders` entry (Effect entry) registers and can be listed/created without remote execution |
| C9 | No machine-service interference | the process does not create the service registration file, does not bind 49374/49375/4094–4296, and (via `/proc/<pid>/fd`) does not open the hub DB; verified while running |
| C10 | Upstream delta + brittleness | list of exports/changes required, and what internal/private imports and version coupling remain (judged from the code actually imported by the prototype) |

Auxiliary observations (non-pass/fail): startup time; whether `SessionRestart.resumeSuspendedSessions` runs; default DB path.

## Procedure

1. Safety envelope for EVERY process: `env -u BUN_INSPECT -u AMICODE_ENGINE_INSPECT`; `XDG_STATE_HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` under `/tmp/opencode/h0c/xdg/<candidate>/`; `OPENCODE_DB` (and `database.path` in code) a fresh file in that dir; listen on 127.0.0.1 only, ports 51000–51999 that are free at the moment of binding (`ss` check first; 51223 is already held by something else); never `serve --service`, never `opencode service`; no credentials, no model calls; password is a throwaway literal.
2. Baseline hash of the hub's unit files / scripts / listening ports before; same after. The hub DB is written continuously by the live hub itself, so it is checked by (a) never being opened by any spike process (`/proc/<pid>/fd` scan) and (b) unit files byte-identical; its own mtime/size are recorded but cannot be required static.
3. For each candidate, a small script in `/tmp/opencode/h0c/` starts the server, runs C1–C9, prints PASS/FAIL lines; raw output saved under `docs/spikes/h0c-prototype/raw/` (copied from `/tmp/opencode/h0c/raw/`).
4. Server-side observation of abort (C6): count active `/api/event` subscribers on the server side (a wrapper counter around the stream body's `cancel`, plus if available the Bus subscriber count / open TCP connections via `ss -tn` on the port) before, during, and after abort.
5. Build the smallest prototype for the leading candidate in `docs/spikes/h0c-prototype/` (NOT a pnpm workspace member) with a check script and README. Then write Results + Decision.

## Decision rule (fixed now)

Prefer the candidate that passes C1–C9 with the **smallest upstream delta and fewest private imports**. A candidate that fails C3 or C6 cannot be chosen without a stated wrapper that fixes it. Ties go to the candidate that keeps plugin registration (C7) and workspace providers (C8) available in-process.
